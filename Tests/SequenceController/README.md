# Проверки контроллера цепочек

Запусти из корневой папки проекта:

```powershell
dotnet run --project Tests/SequenceController/SequenceControllerChecks.csproj
```

Требуется .NET SDK 10. Проверки выполняют код `SequenceController`,
`DialogueController` и `PlayerControlLocks` с упрощёнными заменами Unity и
компонентов действий. Они проверяют независимость блокировок управления,
ожидание закрытия интерфейса диалога, завершение, прерывание, отмену, повторный
запуск, отсутствующие или отключённые компоненты, тайм-ауты, отмену из обработчика
события и режим Timeline Hold. Анимации, физику, сериализацию и отображение эти
проверки не моделируют — их нужно проверить в Unity в режиме Play Mode.

## Настройка в Unity Inspector

Эпизод с поленом в сцене `Assets/Scenes/Act 2 Recover.unity` настроен на объекте
игрока «Диалоги мысли». Его `SequenceController` ждёт закрытия начального диалога,
запускает взмах поленом, дожидается завершения реакции игрока и запускает диалог
мыслей. Цепочку запускает только вариант «Ударить»; вариант «Вернуть полено»
сохраняет прежнее поведение. Сопутствующие события медика находятся в `On Start`
шага удара.

Для настройки другой цепочки:

1. Добавь `SequenceController` на объект, который остаётся активным в течение всей цепочки.
2. Заполни список `Steps` в порядке выполнения. Доступны типы `Dialogue` (диалог),
   `LogSwing` (взмах поленом), `PushReaction` (падение игрока), `Timeline`,
   `Delay` (пауза), `Event` (событие) и `WaitForDialogueClose` (ожидание закрытия диалога).
3. Назначь компоненты и ресурсы, необходимые для выбранных типов. Шаг `Event`
   выполняет `On Start` и сразу завершается: он не ждёт окончания запущенной анимации
   или другого действия, которое продолжается после вызова события.
4. Если цепочка запускается из варианта ответа в диалоге, первым поставь `WaitForDialogueClose`.
5. В запускающем событии вызови `StartSequence()`. Удали из этого события и его
   таймеров прежние вызовы тех же шагов, чтобы они не запускались дважды.
6. Для прерывания вызывай `CancelSequence()`. Необязательный `Timeout` задаётся
   в реальных секундах. Для диалогов оставляй ноль, чтобы время чтения не ограничивалось.

Оставь `Block Player Controls` включённым, чтобы управление блокировалось на всё
время цепочки. Собственные блокировки диалогов и других действий остаются
независимыми. Шаг `Timeline` использует назначенный `PlayableDirector` и его
обычные обработчики запуска и остановки, в том числе существующий `CutSceneController`.
В режиме `Hold` шаг завершается при достижении конца Timeline; зацикленные Timeline
не поддерживаются. Внешний вызов `PlayableDirector.Stop()` считается завершением
шага; для отмены всей цепочки используй `CancelSequence()`.

## Пауза перед падением

Если игрок падает слишком рано, вставь между `LogSwing` и `PushReaction` шаг
типа `Delay`. Укажи длительность в поле `Delay`, например 0,7 секунды, и подбери
её в Play Mode. Во время паузы управление останется заблокированным, а диалог
мыслей по-прежнему дождётся завершения падения.

## Проверка в Play Mode

Пройди эпизод с поленом, удерживая клавиши движения и двигая мышью. Управление
должно оставаться заблокированным во время диалога, удара, падения, мыслей и
финального исчезновения интерфейса, а затем вернуться. Также проверь ветку
«Вернуть полено», отдельный диалог и отдельную кат-сцену. В новой цепочке падение
и мысли запускаются по фактическому завершению предыдущих действий вместо
прежних таймеров на 2,5 и 7 секунд.
